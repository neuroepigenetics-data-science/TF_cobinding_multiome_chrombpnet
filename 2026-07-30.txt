*** DATA CAVEATS — carry these into interpretation ***
  - Endothelial 28% retention: 2nd-most DARs (30,740) from the FEWEST cells
    (439), including 9-cell 3dpi and 30-cell 7dpi contrasts. Underpowered
    comparisons manufacture DARs that don't sit in real peaks; the intersect
    removed ~22,000. Perivascular is the control: nearly as few cells (673) but
    only 4,481 DARs and 81% retention -> it's the thin CONTRASTS, not small
    cell count. Treat Endothelial motifs cautiously.
  - Macrophages 273 regions: uninjured group is only 22 cells. Regions are
    trustworthy (99% in peaks) but FAR too few for MoDISco seqlet clustering.
    Biologically expected (macrophages infiltrate after injury).
  - Peak counts do NOT track depth: Neurons_V yields most peaks (166,693) from
    118M fragments; Microglia fewer (115,626) from 283M.
  - Ependymal is both richest and most validated -> best MoDISco candidate,
    and it is the reactive population central to the paper. RNA agrees
    (Ependymal highest at 13,828 DEGs).

BUGS FOUND IN THE PUBLISHED CODE (all documented in script headers)
------------------------------------------------------------------
1. prepare_ml_input.R:32  `ifelse(condition == "Uninj", ...)` never matches —
   this object's levels are 1dpi/28dpi/3dpi/7dpi/**U**. As written it labels all
   15,578 uninjured cells as injured. We use the object's precomputed
   cluster_ids_injury and VERIFY it (0/67,072 mismatches — the object's labels
   are fine; only the script is broken).
2. DAR BEDs duplicated across timepoints. 48% of Ependymal and Microglia rows
   were duplicates; the original emits each 2-4x, so MoDISco would double-count
   seqlets in persistently-open regions and inflate those motifs. Now collapsed
   (ml.dars_dedupe: true; set false for published behaviour).
3. differential_analysis.R relies on the object's saved active ident
   (`Idents(multiome) %>% unique()`) — silently changes the whole analysis.
   Now set explicitly from config.
4. run_chrombpnet.sh references mm10.chrom.sizes AND mm10.chr.sizes (only the
   latter exists); has a stray `A` in `-n negatives/A${i}_nonpeaks_negatives.bed`;
   writes <ct>_chr.bed to celltype_fragments_multiome_only/ but READS it from
   ML/celltype_fragments/. NOT yet fixed — do it before running on the GPU box.
5. The DAR x peak intersect run_chrombpnet.sh expects
   (dars_intersect_peaks/<ct>_intersect_dars.bed) exists in NEITHER published
   script. We produce it (call_celltype_peaks.sh step 4, `bedtools intersect -u`
   keeping whole 500bp DAR regions, since ChromBPNet wants fixed-width input).

ENVIRONMENT / TOOLING GOTCHAS HIT
---------------------------------
- Signac stores an md5 PAIR (fragment file + .tbi). ValidateHash() requires BOTH.
  Zamboni never shipped her .tbi files (ours are tabix-regenerated), so
  UpdatePath() fails, AND `Fragments(assay)<-` fails again inside AddFragments().
  Fix: verify the FRAGMENT file against her stored hash[1] (all 21 matched),
  then re-stamp the hash pair with our local files.
- FindMarkers dies with `vector memory exhausted` on the largest cell type.
  Object is 18.8 GB loaded (4 assays, 5 reductions, 4 67k x 67k graphs).
  DietSeurat() to one assay -> 11.5 GB (peaks) / 3.8 GB (RNA). Use
  `--only peaks` / `--only rna`, never `both`.
- DietSeurat() refuses to drop the DefaultAssay -> `--only rna` failed where
  `--only peaks` passed by luck. Repoint DefaultAssay before slimming.
- macs2/bedtools were hardcoded to /Users/gorkemdurmaz/... paths. Now
  env var -> pipeline/tools.local.env (gitignored, host-specific) -> PATH, and
  the resolved path is checked to be EXECUTABLE (not merely non-empty).
- macOS bash is 3.2: empty array expansion under `set -u` errors.
- .gitignore does not support trailing comments (the comment becomes part of the
  pattern and silently matches nothing).
- Use miniconda's snakemake (/Users/gorkemdurmaz/miniconda3/bin/snakemake);
  `conda run -n zamboni-r snakemake` hits a broken system-python numpy ABI.
- This Mac idle-sleeps and killed a run. Launch long jobs detached under
  `caffeinate -i -m -s`, plus a `caffeinate -w <pid>` guard (the backgrounded
  process reparents to PID 1, so the wrapper's child link is unreliable).
